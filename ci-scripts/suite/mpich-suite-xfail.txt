# Expected failures in MPICH's Fortran test suite.
#
# test-mpich-suite.sh, beside this file, compares each run against it and fails
# on any difference in either direction: a test that fails and is not listed
# here, and a test that is listed here and passes. The second matters as much as
# the first -- without it the list rots, an entry outliving the problem it stands
# for and quietly guarding nothing.
#
# Names rather than counts, because counts hide a swap: one test starting to
# fail while another starts passing leaves the total unchanged.
#
# Two kinds of line, both ignoring anything after a `#`:
#
#   triaged <mpi>/<toolchain>/<os>/<os-version>/<arch>
#       Declares that this variant's failures are all listed below, so the run
#       may fail on a difference. A variant with no `triaged` line is still
#       compared and reported, but cannot fail the build -- that is how a variant
#       nobody has measured yet stays honest rather than being papered over with
#       a blanket exception.
#
#       Since the version is part of the key, moving a runner to a newer OS makes
#       its variant an unmeasured one, and the suite stops gating there until it is
#       measured and a line added. The run says so in as many words, and the
#       `os:` list in .github/workflows/ci.yaml pins the images, so this happens
#       when someone edits that list and not behind their back. There is one such
#       list per stage there, and the `checks` job asserts that they agree -- so
#       that "someone edits that list" cannot mean editing four of the five.
#
#   xfail <mpi>/<toolchain>/<os>/<os-version>/<arch> <language> <test>   # why
#       One expected failure. `*` matches any one component of the variant.
#       The reason is not decoration: an entry that cannot say why it is here is
#       an untriaged failure being hidden, and should say *that*.
#
#   flaky <mpi>/<toolchain>/<os>/<os-version>/<arch> <language> <test>   # why
#       A test that fails or passes from run to run. Judged neither way, and
#       reported on every run so that it cannot go quiet. This is a weaker claim
#       than `xfail` and wants a reason for the flakiness, not just for the
#       failure -- reach for it only when a test has actually been seen to
#       change its mind, since it gives up both halves of the comparison.
#
# <mpi> is mpich or openmpi, <toolchain> gcc or llvm, <os> the lowercased
# `uname -s`, <os-version> a distribution's VERSION_ID or the major version of
# macOS or FreeBSD, and <arch> `uname -m` -- so darwin/15/arm64,
# linux/24.04/x86_64, linux/26.04/aarch64 or freebsd/14/amd64. <language> is
# f77, f90 or f08.
#
# `uname -m` is the machine's own word for the architecture and not a normalised
# one: the same 64-bit x86 is x86_64 on Linux and macOS and amd64 on FreeBSD. So
# an entry that is really about 64-bit-ness -- `attrmpi1f08` below is the example,
# listed once per 64-bit arch -- needs a line per spelling, and a `*/*/*/*/x86_64`
# selector says nothing about FreeBSD.
#
# Both of the last two are in the key because environments that agree on
# everything else still disagree -- and not always over the thing the component
# names. The architecture went in for eleven Open MPI spawn tests that fail on
# x86_64 and pass on aarch64 -- a spawned child that Open MPI cannot reach over TCP
# there and can here, for reasons not established. Two MPICH tests differ the other
# way and keep it in the key. The OS version went in for the Docker
# images, which run Ubuntu 26.04 where CI's runners run 24.04 and part company over
# MPI_Dist_graph_create and i_fcoll_test, and because this repository's own macOS is
# 26 where the runners are 15. Read either component as "a different environment"
# rather than as a claim about the instruction set or the release.
#
# The version is deliberately coarse. A full macOS version, or a distribution's
# point release, would churn every time a runner image is refreshed and expire
# expectations that had nothing wrong with them.
#
# Measured across all twelve variants in CI, plus two environments outside it.
# There are no `flaky` entries at the moment. The last three -- `typecntsf`,
# `typecntsf08` and `typecntsf90`, MISSING.md "MPI_Type_get_contents converts
# uninitialised memory" -- were removed after three consecutive clean CI runs
# (30936230034, 30941008705, 30951119166) once the alltoallw handle-array fix
# in 96bcc29 took the two entries that had been the evidence they still fired,
# `nonblocking_inpf` and `nonblocking_inpf90`, out of the picture.
#
# Where a reason names an entry in MISSING.md, that entry is the record; where it
# says "untriaged", nobody has looked yet, and the symptom is quoted so that
# looking can start from something. Every reason that is not "untriaged" is
# either in MISSING.md or self-contained here -- that is the property to keep
# when adding an entry.
