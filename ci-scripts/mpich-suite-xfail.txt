# Expected failures in MPICH's Fortran test suite.
#
# ci-scripts/test-mpich-suite.sh compares each run against this file and fails
# on any difference in either direction: a test that fails and is not listed
# here, and a test that is listed here and passes. The second matters as much as
# the first -- without it the list rots, an entry outliving the problem it stands
# for and quietly guarding nothing.
#
# Names rather than counts, because counts hide a swap: one test starting to
# fail while another starts passing leaves the total unchanged.
#
# Two kinds of line, both ignoring anything after a `#`:
#
#   triaged <mpi>/<toolchain>/<os>/<arch>
#       Declares that this variant's failures are all listed below, so the run
#       may fail on a difference. A variant with no `triaged` line is still
#       compared and reported, but cannot fail the build -- that is how a variant
#       nobody has measured yet stays honest rather than being papered over with
#       a blanket exception.
#
#   xfail <mpi>/<toolchain>/<os>/<arch> <language> <test>   # why
#       One expected failure. `*` matches any one component of the variant.
#       The reason is not decoration: an entry that cannot say why it is here is
#       an untriaged failure being hidden, and should say *that*.
#
# <mpi> is mpich or openmpi, <toolchain> gcc or llvm, <os> the lowercased
# `uname -s` and <arch> `uname -m` -- so darwin/arm64, linux/x86_64 or
# linux/aarch64. <language> is f77, f90 or f08.
#
# The architecture is part of the key because the two Linux runners disagree:
# eleven Open MPI spawn tests fail on x86_64 and pass on aarch64, and two MPICH
# tests differ the other way. Without it those would read as unexpected passes on
# whichever runner went second.
#
# Everything here was measured in one CI run across all twelve variants, except
# mpich/gcc/darwin/arm64, which also matches a local run on a different machine
# and different compilers. One measurement is thin evidence for a flaky test, so
# expect some churn: a flaky entry shows up as an unexpected pass, which is the
# mechanism working rather than failing.
#
# Where a reason names an entry in MISSING.md, that entry is the record; where it
# says "untriaged", nobody has looked yet, and the symptom is quoted so that
# looking can start from something.

triaged mpich/gcc/darwin/arm64

triaged mpich/gcc/linux/aarch64
triaged mpich/llvm/darwin/arm64
